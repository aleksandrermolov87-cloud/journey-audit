# G-08 · P1 · An unchanged address is confirmed without typing and shown on the summary

## Problem
The user types a full delivery address on a phone in a moving train (s7): about 40 keystrokes, 25.3 of 45.2 s of the model's KLM time. The summary (s8) does not show the address, so a wrong or outdated one goes unnoticed.
Findings: LOAD-01 (high, med, provided), CJM-13 (medium, med, provided), EDGE-06 (high, med, synthetic).

## Goal and metric
- Orders with the address confirmed without typing · now: 0 % · target: ≥ 80 % · how: `reissue_address_confirmed{source=profile}` / `reissue_confirmed`.
- Time on the address step for an unchanged address · now: 25.3 s (KLM model) · target: median ≤ 5 s · how: `reissue_address_shown` → `reissue_address_confirmed`.
- Cards returned for a wrong address · now: not measured · target: baseline first.

## Scope
- s6–s7 → address from the profile preselected, Edit opens the existing field with suggestions.
- s8 → summary shows the address with Edit.
- Out of scope: card design and name fields (P2, owner decision 7).

## TO BE journey (fragment)
| Step | User does | Sees | Response | Undo / way back |
|---|---|---|---|---|
| 6 | Opens the order form | "Deliver to: <address> · from your profile" | — | Back |
| 7 | Taps "Use this address" or "Edit" | Edit: field with suggestions | — | Cancel edit |
| 8 | Reads summary | Fee, date, address with Edit | — | Edit |

## States
| State | What the user sees | What they can do |
|---|---|---|
| Profile address exists | Prefilled, marked "from your profile" | Confirm, edit |
| No profile address | Empty field with suggestions | Type |
| Offline while editing | Draft kept, "We will save it when you are back online" | Continue later |
| Undeliverable address | Reason and suggestion | Edit |

## UI copy
- "Deliver to" / "<address>" / "From your profile"
- Buttons: "Use this address" · "Edit"
- Summary row: "Delivery address" · "Edit"

## Acceptance criteria
- Given a profile address, When the form opens, Then it is preselected and marked "from your profile".
- Given the user taps "Use this address", Then no keyboard opens.
- Given the summary, Then the full address is shown with Edit.
- Given the user edits on the summary, Then they return to the summary with the new address.
- Given the connection drops while editing, Then the typed draft is kept.

## Analytics
`reissue_address_shown{source}` · `reissue_address_confirmed{source=profile|edited, ms}` · `reissue_address_edited{place=form|summary}`.

## Test cases
- Profile address → confirm → summary shows it.
- User moved: edit on summary → new address saved for the order.
- Negative: no profile address → typing with suggestions.
- Accessibility: Edit buttons have names with context ("Edit delivery address").

## Do not break
- The summary remains the final check before ordering.

## Owner decisions
- Whether an edited address updates the profile or only this order.

## Dependencies and effort
Profile address API, form state. **M**.
