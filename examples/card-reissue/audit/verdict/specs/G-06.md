# G-06 · P1 · Choosing a block type cannot strand the user without a new card

## Problem
The dialog asks "temporarily or permanently?" without saying what each does (s3, moment of truth). The map's failure note: a temporary block does not allow a new card later; recovery unknown. 2 of 3 synthetic personas could not tell the options apart; the 66-year-old persona chose temporary because "permanent" read as irreversible.
Findings: CJM-06 (high, provided), EDGE-03 (high, med, synthetic). LOAD-05 is a constraint: keep the choice (useful friction).

## Goal and metric
- Temporary blocks from "Lost or stolen" followed by a permanent block or reissue within 24 h · now: not measured · target: < 5 % · how: `card_blocked{type=temporary, entry=lost}` → `card_block_upgraded`.
- Temporary blocks with a route to reissue · now: none · target: 100 %.

## Scope
- s3 dialog → outcome labels, permanent preselected from the "Lost or stolen" entry, irreversibility stated.
- Temporarily blocked card → "Block for good and order a new card" available (branch e3).
- Out of scope: cancelling an order (deferred, EDGE-09).

## Acceptance criteria
- Given the dialog opens from "Lost or stolen", Then permanent is preselected.
- Given either option, Then its line states whether it can be undone and whether a new card follows.
- Given a paused card, When the user opens it, Then "Block for good" leads to the reissue entry.
- Given permanent is chosen, Then no screen says it can be undone.
