# G-03 · P0 · Blocking starts with one tap from the home screen

## Problem
Owner vision V1: "blocking takes one tap from the home screen". The map needs a tap on the card tile, then card settings with 9 actions, then "Block card", then a choice dialog (s1–s3). s2 is the load peak for every profile (index 36.6 for the main persona, 45.8 for low/low).
Findings: CJM-02 (critical, provided), LOAD-04 (medium, provided).

## Goal and metric
- Taps from home to "card blocked" · now: 4 (map) · target: 2 (entry + confirm) · how: count of `ui_tap` between `home_shown` and `card_blocked`.
- Time from app open to confirmed block · now: 10.6 s KLM model for s1–s3 · target: median ≤ 20 s in real use, baseline to capture · how: `app_open` → `card_blocked`.

## Scope
- s1 → card tile shows "Lost or stolen?".
- s2 → removed from the main path; the 9-action screen stays reachable for other tasks.
- s3 → opens directly, permanent preselected (labels: G-06).
- Out of scope: the content of the dialog options (G-06).

## TO BE journey (fragment)
| Step | User does | Sees | Response | Undo / way back |
|---|---|---|---|---|
| 1 | Opens the app | Home; card tile with "Lost or stolen?" | — | — |
| 2 | Taps "Lost or stolen?" | Block dialog for card •• 1234, permanent preselected | — | Cancel |
| 3 | Taps "Block card" | Progress (G-02) | Block request | — |

## States
| State | What the user sees | What they can do |
|---|---|---|
| Default | "Lost or stolen?" on each card tile | Open the dialog |
| Several cards | Each tile has its own action with last 4 digits | Pick the right card |
| Card already blocked | Tile says "Blocked" with "Order a new card" | Go to reissue (G-07) |

## UI copy
- Tile action: "Lost or stolen?"
- Dialog heading: "Block card •• 1234"
- Primary button: "Block card" · secondary: "Cancel"

## Acceptance criteria
- Given an active card, When home loads, Then "Lost or stolen?" is visible on its tile without scrolling.
- Given the user taps it, When the dialog opens, Then it names the card's last 4 digits and permanent is preselected.
- Given the dialog is open, When the user taps "Block card", Then the block starts with no further screens.
- Given the user taps "Cancel", Then they return to home with nothing changed.
- Given a blocked card, When home loads, Then the tile shows "Blocked" and no "Lost or stolen?".

## Analytics
`lost_card_entry_tapped{source=home_tile|card_screen}` · `block_dialog_opened{preselected}` · `block_dialog_cancelled` · `card_blocked{type, taps, ms_from_open}`.

## Test cases
- Home → "Lost or stolen?" → "Block card" → progress: 2 taps.
- Entry from the card screen still works.
- Two cards: each tile opens the dialog for its own card.
- Negative: "Cancel" leaves the card active and logs `block_dialog_cancelled`.
- Accessibility: the tile action has an accessible name with the card digits; target size ≥ 44×44 pt.

## Do not break
- The confirmation tap stays: the block is irreversible (useful friction, LOAD-05).
- Other card actions remain on the card screen.

## Owner decisions
- Owner decision 4: does V1 "one tap" include the confirmation? Default: one tap opens the dialog, the confirm tap stays.

## Dependencies and effort
Home tile layout, deep link into the dialog. **M**: changes the home screen used by every user.
