# G-07 · P1 · The blocked card and the order stay visible until the new card is active

## Problem
After blocking, the home screen loses the card tile (s10). If the user leaves between blocking and ordering, the route back to reissue is not described. After the order, status depends on one push (s9), and issuer rejection is not described. The map stops at "closes the app".
Findings: CJM-10 (high, absent), CJM-15 (medium, absent), EDGE-04 (high, med, provided).

## Goal and metric
- Users with a blocked card or pending order who see its status on home at the next visit · now: 0 % (tile removed) · target: 100 % · how: `home_card_status_shown{state}`.
- "Where is my card" contacts per 100 orders · now: not measured · target: −30 % from baseline · how: support tags.

## Scope
- s10 home → status tile for the card until the new one is activated.
- s9 → in-app order status and a rejection state.
- Push reminder if the card is blocked and no order is placed (branch e5).
- Out of scope: activation and PIN flow details (adjacent journey).

## TO BE journey (fragment)
| Step | User does | Sees | Response | Undo / way back |
|---|---|---|---|---|
| 9 | Opens home after blocking, no order | Tile "Card •• 1234 blocked · Order a new card" | — | — |
| 9' | Opens home after ordering | Tile "New card ordered · arrives by <date>" | Push on status change | Track order |
| 9'' | Order rejected by issuer | Tile "We could not order your card" with reason | — | Try again, contact us |

## States
| State | What the user sees | What they can do |
|---|---|---|
| Blocked, no order | Tile with "Order a new card" | Order |
| Ordered | Date and status | Track |
| Shipped | "On its way, arrives by <date>" | Track |
| Delivered | "Activate your new card" | Activate |
| Rejected | Reason and next step | Retry, contact |

## UI copy
- "Card •• 1234 blocked" / "Order a new card"
- "New card ordered" / "Arrives by <date>"
- "We could not order your card" / "<reason in plain words>" / "Try again"
- Reminder push: "Your card is blocked. Order a new one in the app."

## Acceptance criteria
- Given a blocked card without an order, When home loads, Then the tile offers "Order a new card".
- Given an order, When home loads, Then the tile shows status and date without opening push.
- Given the issuer rejects the order, Then the tile shows the rejection with a next step within 1 min of the event.
- Given no order 24 h after blocking, Then one reminder push is sent.

## Analytics
`home_card_status_shown{state}` · `reissue_order_status_changed{from, to}` · `reissue_order_rejected{reason}` · `reissue_reminder_sent` · `reissue_started{entry=home_tile|reminder|confirmation}`.

## Test cases
- Block → leave → reopen → order from the tile.
- Order → status changes → tile updates without push.
- Negative: issuer rejection → state with retry.
- Negative: push disabled → status still visible in the app.
- Accessibility: status text not conveyed by color alone.

## Do not break
- Virtual card tile from G-01 stays next to the order status.

## Owner decisions
- Issuer rejection reasons that may be shown to users.

## Dependencies and effort
Order status API from the issuer, home tile states. **M**.
