# Спеки, TO BE, проверка

## Спека цели — `specs/G-NN.md`

Спека нужна, чтобы дизайнер, разработчик или агент кода сделал исправление без повторного аудита. Пиши так, чтобы её можно было отдать в задачу как есть.

```markdown
# G-01 · P0 · <цель одной фразой>

## Проблема
Что сейчас происходит с пользователем, 2–4 строки. Ссылки на находки (CJM-03, EDGE-01, LOAD-05) и классы доказательности.

## Цель и метрика
Метрика · сейчас · цель · как измерить.

## Объём
Затронутые шаги AS IS (id) → что меняется. Что вне объёма.

## Путь TO BE (фрагмент)
| Шаг | Пользователь делает | Видит | Отклик | Обратное действие |
Только изменённые и новые шаги.

## Состояния
| Состояние | Что видит пользователь | Что может сделать |
По умолчанию · загрузка · пусто · ошибка · офлайн · отказ / вне границ · частичный результат — только те, что относятся к цели.

## Тексты интерфейса
Точные строки: заголовки, кнопки, ошибки, подсказки. Слова пользователя, без внутренних терминов. Если текст требует юридического или медицинского согласования, пометь.

## Критерии приёмки
- Дано … Когда … Тогда …
(3–8 штук, каждый проверяемый тестом или ручной проверкой)

## Аналитика
События с параметрами, по которым считается метрика.

## Тест-кейсы
Из краевых сценариев семейства edge и веток: вход → ожидаемый результат. Включи как минимум один негативный и один на доступность.

## Что не ломать
Пики из кривой эмоций, полезное трение, пункты видения, которые уже закрыты.

## Решения владельца
Вопросы, без ответа на которые спеку нельзя закончить. Варианты, если они есть.

## Зависимости и усилие
Контракты, бэкенд, контент, ревью. S / M / L с одной строкой обоснования.
```

Для P2 спек не пиши: достаточно строки в таблице целей с `fix_hint`.

## `verdict.json`

```json
{
  "verdict": "Доработать",
  "verdict_reason": "одна строка",
  "files": {"verdict.md": "<markdown>", "specs/G-01.md": "<markdown>"}
}
```

Оркестратор разворачивает `files` командой `journey_check.py render <work>`.

## TO BE

Полная таблица пути в том же формате, что исходник (те же колонки), с изменениями от всех P0 и P1. Под таблицей diff:

- **Добавлено**: шаг → цель
- **Убрано**: шаг → цель
- **Разделено**: шаг → на какие
- **Изменено**: шаг → что именно
- **Оставлено как полезное трение**: шаг → почему

Если цели требуют решения владельца, покажи TO BE с вариантом по умолчанию и отметь развилку.

## Проверка на людях

5–8 заданий для юзабилити-теста или интервью. Каждое привязано к цели и гипотезе:

```
1. G-01 · гипотеза: после блокировки карты пользователь не знает, как платить сегодня
   Задание: «Вы только что заблокировали потерянную карту. Купите кофе с телефона.»
   Участники: 5 человек, ездящих на работу, 2 из них 55+
   Успех: ≥ 4 из 5 оплачивают за 3 минуты без помощи
```

Сначала проверяй гипотезы, на которых держатся P0 с уверенностью med или low.
