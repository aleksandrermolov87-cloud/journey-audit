# Семейство: вердикт, приоритеты, спеки

> Русская версия `SKILL.md`. Справочники — `references/ru/`.

Вопрос семейства: **что из найденного чинить, в каком порядке, какой результат считать исправлением и как это проверить.** Новые находки здесь не ищутся. Если при сведении виден пробел, который не закрыло ни одно семейство, запиши его в «Не проверено», а не в бэклог.

## Вход

`<work>/cjm/findings.json`, `<work>/edge/findings.json`, `<work>/load/findings.json` (и их `report.md` для контекста), `<work>/journey.json`, `<work>/frame.md`, `<work>/edge/branches.json`, если есть.

Проверь вход: `python3 <Script> findings <work> --lang ru`. Если семейства нет или его файл не проходит контракт, работай с остальными и напиши в вердикте, какой оси не хватает.

## Методы

| # | Метод | Файл |
|---|---|---|
| 1 | Склейка дублей и разрешение конфликтов | `references/ru/merge-and-conflicts.md` |
| 2 | Приоритеты P0–P2 | `references/ru/prioritization.md` |
| 3 | Цели с метриками | `references/ru/prioritization.md` → «Цели» |
| 4 | Спеки | `references/ru/spec-format.md` |
| 5 | TO BE и план проверки | `references/ru/spec-format.md` → «TO BE» и «Проверка на людях» |

Стартовые кластеры и баллы:

```bash
python3 <Script> merge <work> > <work>/verdict/merged.json
```

Скрипт группирует находки по `root_cause` и общим шагам и считает стартовый балл. Склейка по смыслу, приоритет и формулировка цели — твои решения: смысла скрипт не видит.

## Вердикт по пути

Одно из четырёх, с обоснованием в одну строку:

| Вердикт | Когда |
|---|---|
| Готов | Нет P0, P1 не больше 2 |
| Готов с условиями | Нет P0, но есть P1, без которых нельзя выпускать на заявленную аудиторию |
| Доработать | Есть P0, решаемые в рамках текущего пути |
| Переделать | P0 касается главной задачи или ценности: путь в текущей форме не решает то, ради чего пользователь пришёл |

## Выход

При запуске из оркестратора markdown-файлы кладутся строками в `<work>/verdict/verdict.json` → `files` (ключ — относительный путь), оркестратор разворачивает их командой `journey_check.py render <work>`. При прямом вызове, если запись `.md` разрешена, пиши файлы сразу.

- `verdict.md`: вердикт, сводка по семействам, таблица целей P0–P2, конфликты и как разрешены, что сохранить (пики, полезное трение), TO BE с diff, план проверки на людях, решения владельца, не проверено, заметки о методе.
- `specs/G-NN.md` — спека на каждую цель P0 и P1.
- `<work>/verdict/backlog.json` — цели в машиночитаемом виде (схема в `references/ru/spec-format.md`).

## Границы

- Не принимай за владельца решения о границах сервиса, юридических, медицинских и финансовых рамках. Формулируй варианты и выноси в «Решения владельца». Пример: «обещать дату доставки» может требовать обязательств логистики — это не правка интерфейса.
- Цель без метрики — не цель. Если метрику сейчас не измерить, напиши, что для этого нужно.
- Не повышай уверенность при сведении: три синтетических подтверждения — всё ещё гипотеза, просто с большим весом.
