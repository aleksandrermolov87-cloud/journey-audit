# Второстепенные и нестандартные сценарии

Цель: найти пути, которые основная карта обходит, и решить, какие из них нужно описать отдельно.

## Оси E01–E14

Проходи по каждому этапу пути. Ось, которая к пути не относится, пропусти и отметь, почему.

| ID | Ось | Что спрашивать |
|---|---|---|
| E01 | Вход | Пришёл не с главной: по ссылке из письма, из поиска, по закладке на внутренний шаг, по QR, из другого продукта. Пришёл без контекста, который карта считает известным |
| E02 | Прерывание и возврат | Закрыл вкладку посреди процесса, сел телефон, вернулся через час, через неделю, с другого устройства. Что сохранилось, что потеряно, понимает ли он, где остановился |
| E03 | Повторный и опытный пользователь | Второй раз тот же путь. Нужны ли снова согласие, онбординг, подсказки. Есть ли короткий путь |
| E04 | Данные пользователя | Пусто, слишком длинно, ошибка в данных, данные другого человека, документ плохого качества, частично заполнено, не тот формат, не тот язык, устаревшие данные |
| E05 | Порядок и повтор | Двойной клик, повторная отправка, шаги в другом порядке, назад браузером, обновление страницы, две вкладки одновременно |
| E06 | Права и роли | Другая роль (родственник, бухгалтер, сотрудник, админ), нет прав, истёк доступ, общий аккаунт, представитель по доверенности |
| E07 | Внешние зависимости | Сервис упал, ответил медленно, ответил частично, ответил неожиданным форматом. Платёж прошёл, а подтверждение нет |
| E08 | Время | Выходные, ночь, истёк срок документа или кода, изменились правила между визитами, часовой пояс |
| E09 | Устройство и окружение | Маленький экран, одна рука, плохая сеть, шум, чужое устройство, режим экономии, крупный шрифт |
| E10 | Доступность | Скринридер, только клавиатура, дальтонизм, снижение моторики, когнитивные особенности, ограниченное владение языком |
| E11 | Границы сервиса | Вопрос вне компетенции, запрос, который сервис не должен выполнять, срочная ситуация. Есть ли куда перенаправить |
| E12 | Ценность не получена | Ответа нет, услуги нет, данных нет. Это не ошибка интерфейса, а провал ценности: что пользователь получает взамен |
| E13 | Эмоциональное состояние | Тревога, спешка, недоверие, усталость после предыдущего шага. Тот же экран в таком состоянии читается иначе |
| E14 | Выход и последствия | Хочет удалить данные, отозвать согласие, оспорить результат, переслать результат другому, распечатать |

## Оценка и ранжирование

Для каждого найденного сценария:

- **Частота** (1–3): 1 — редко, 2 — регулярно у части аудитории, 3 — у заметной доли пользователей.
- **Ущерб** (1–3): 1 — неудобство, 2 — потеря времени или данных, 3 — неверное решение, вред, юридический риск, уход.
- **Покрытие**: `описан` / `частично` / `нет`.
- **Приоритет** = частота × ущерб, плюс 2, если покрытие `нет`.

Топ-5 по приоритету разверни в альтернативные пути (3–8 шагов, формат `journey-audit/references/ru/journey-format.md`, раздел `branches`, файл `edge/branches.json`). Остальное — таблица.

## Смежные пути

Отдельно предложи 3–5 путей, которые заслуживают своей карты, с одной строкой обоснования:

- провал, достаточно серьёзный, чтобы стать отдельным путём (спор, возврат, отмена, жалоба);
- персоны, которые подразумеваются, но не описаны (родственник, специалист поддержки, эксперт);
- что было до первого шага и что будет после последнего;
- частые краевые случаи, которые основной путь проходит одной строкой.

Не создавай эти карты сам, предложи список по приоритету.
