# Формат journey.json

Одна схема на все шаги аудита: логика, краевые пути, нагрузка, видение. Обязательные поля отмечены `*`. Остальные заполняй, когда есть данные: пустое поле лучше выдуманного.

Рабочий пример целиком — `examples/card-reissue/journey.json` в репозитории. Значения-коды (`actor`, `tech`, `status`…) всегда латиницей, тексты — на языке пользователя.

```json
{
  "title": "Перевыпуск потерянной карты",
  "source": "ai | human | code | mixed",
  "persona": {
    "name": "Едет на работу, 47 лет, потерял карту",
    "tech": "low | mid | high",
    "patience": "low | mid | high",
    "context": "мобильное приложение, стоит в электричке, 10 минут",
    "goal": "заблокировать карту и получить новую без визита в отделение"
  },
  "jtbd": "Чтобы никто не потратил мои деньги и я мог платить сегодня",
  "trigger": "Заметил, что пропал кошелёк",
  "scenario": "main | <название краевого сценария>",
  "success": "Старая карта заблокирована, новая заказана, понятно, как платить до её получения",
  "owner_vision": [
    {"id": "V1", "expect": "Блокировка — одно нажатие с главного экрана", "steps": ["s2"], "origin": "owner"},
    {"id": "V2", "expect": "Платить можно сегодня виртуальной картой", "steps": [], "origin": "бриф продукта, раздел «Цели»"}
  ],
  "internal_terms": ["reissue_flow", "эмиссия"],
  "allowed_terms": ["ИНН"],
  "steps": [
    {
      "id": "s1",
      "stage": "Обнаружение",
      "actor": "user | system | external",
      "action": "Открывает банковское приложение",
      "response": "Главный экран с балансом и плиткой карты",
      "channel": "mobile app",
      "feeling": -1,
      "feeling_reason": "Тревога: кошелька нет",
      "moment_of_truth": false,
      "src": "карта от ИИ, строка 1",
      "evidence": "",
      "assumption": true,
      "failure": "",
      "recovery": "",
      "failure_severity": "",
      "status_feedback": true,
      "load": {
        "decisions": 1, "max_options": 6, "fields": 0, "new_terms": 0,
        "memory_items": 0, "context_switches": 0, "wait_s": 0, "uncertainty": 1,
        "klm": "M P B B"
      }
    }
  ],
  "branches": [
    {"id": "b1", "from": "s4", "title": "Блокировка не прошла", "steps": ["…тот же формат шагов, id b1.s1, b1.s2…"]}
  ]
}
```

## Поля шага

| Поле | Смысл | Правило |
|---|---|---|
| `id`* | Стабильный идентификатор | `s1`, `s2`… В ветках пиши полный id `b1.s1`; скрипт примет и короткий `s1` внутри ветки и добавит префикс. В `owner_vision.steps` всегда полный id |
| `actor`* | Кто действует | Действия системы и внешних сервисов — отдельные шаги, если они занимают время или могут сломаться |
| `action`* | Одно действие | Глагол + объект. Два глагола через «и затем» — повод разделить |
| `response` | Что пользователь видит в ответ | Пусто у шага пользователя — находка L06 |
| `feeling` | −2…+2 относительно прошлого шага | Без `feeling_reason` — находка L08 |
| `src` | Где во входе взят шаг | Строка карты, экран, файл кода. Это не доказательство поведения |
| `evidence` | Данные о реальном поведении или проверенном состоянии продукта | Интервью, аналитика, запись сессии, прогон стенда, `code: routes.ts`. Строка карты сюда не идёт. Пусто — догадка, и L10 сработает на моменте истины |
| `assumption` | Значение выведено, а не взято из источника | `true` для всего, что ИИ додумал |
| `failure` / `recovery` | Что ломается и как выйти | Сбой без выхода — L05. `recovery: "unknown"`, если во входе не сказано (medium вместо high/critical) |
| `failure_severity` | Ручная тяжесть L05 | По умолчанию critical на моменте истины, иначе high. Понижай, если выход очевиден из интерфейса |
| `status_feedback` | Есть ли индикатор состояния при ожидании | Нужен при `wait_s ≥ 1` |
| `moment_of_truth` | Шаг, на котором пользователь решает, остаться ли и доверять ли | Без доказательства — L10 |
| `load` | Признаки для модели нагрузки | См. `journey-load/references/ru/cognitive-load.md`. У шагов системы — только `wait_s` и `uncertainty` |
| `load.wait_s` | Ожидание, с | Число или `"unknown"`. Неизвестная длительность — сама находка L14, не ставь 0 |

## Поля корня

| Поле | Смысл |
|---|---|
| `owner_vision[].status` | `covered` / `at-risk` / `violated` / `not-mentioned`. Ставит аудитор логики после сверки; без него скрипт считает пункт закрытым, если есть ссылки на шаги |
| `owner_vision[].origin` | `owner` — от владельца; иначе откуда восстановлено. Отчёты помечают восстановленное видение |
| `internal_terms` | Внутренние слова продукта, которые пользователь видеть не должен (регулярка не ловит кириллицу) |
| `allowed_terms` | Понятные аудитории аббревиатуры; PDF, JPEG, PNG, HEIC, SMS, QR, PIN, CVV разрешены по умолчанию |

## Как нормализовать чужую CJM

1. Строки таблицы «этап» разбей на шаги-действия. Колонки «что делает / что видит / отклик» → `action` / `response`.
2. Колонка «обратное действие» или «ошибки» → `failure` + `recovery` или отдельная ветка.
3. Если эмоций в источнике нет, проставь их сам с `assumption: true` и причиной.
4. Перечисли в `frame.md`, что пришлось додумать. Этот список сам показывает, где путь недоопределён.
