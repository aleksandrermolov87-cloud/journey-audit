# Рабочая папка и итоговый отчёт

Язык — язык пользователя. Регистр: факты, цифры, следствия, без оценочных слов. Итоговый `journey-audit-<slug>.md` короткий: подробности лежат в отчётах семейств и вердикте, итог на них ссылается.

## Рабочая папка

```
<work>/
  frame.md                 рамка, видение, входы, что додумано при нормализации
  journey.json             нормализованный путь (общий для всех агентов, только чтение)
  cjm/     findings.json · report.md · emotion-curve.svg
  edge/    findings.json · report.md · branches.json · personas.json
  load/    findings.json · report.md · journey.load.json · load-overrides.json · load-*.json · load-curve.svg
  verdict/ verdict.json · verdict.md · backlog.json · merged.json · specs/G-NN.md
  journey-audit-<slug>.md  итог
```

## Итог (оркестратор)

```markdown
# Аудит пути: <название>
Рамка (5–8 строк) · версия входа (коммит, дата)

## Вердикт
Вердикт и обоснование одной строкой (из verdict.md).

## Сводка
Находки по семействам и тяжести; кластеров после склейки; P0 / P1 / P2; пиковая нагрузка; точки ухода;
исходы персон; видение: закрыто / под риском / нарушено / не упомянуто.

## Цели P0 и P1
| Цель | Приоритет | Метрика (сейчас → цель) | Спека | Находки |

## Решения владельца
## Не проверено
## Файлы
Ссылки на отчёты семейств, вердикт, спеки, JSON.
```

## Одно семейство без оркестратора

Если скилл семейства вызван напрямую, его отчёт строится по тем же разделам, что `report_md` в `findings-contract.md`: проверено, находки, артефакты, не проверено, заметки о методе. Находки — в том же JSON, так что вердикт можно запустить позже.
