# Контракт находок

Все три аудитора пишут находки в одном формате, иначе вердикт не сравнит и не склеит их. `journey_check.py findings <work>` проверяет контракт. Значения-коды в JSON — латиницей (так файлы разных языков склеиваются), тексты (`title`, `detail`…) — на языке пользователя. Для тяжести скрипт принимает и русские буквы К/В/С/Н.

## `<family>/findings.json`

```json
{
  "family": "cjm | edge | load",
  "journey": "journey.json",
  "mode": "full | quick",
  "methods": ["L01–L20", "emotion-curve", "health-review"],
  "not_checked": ["L16 — нет снимков интерфейса"],
  "summary": "2–4 строки с цифрами",
  "report_md": "# Логика CJM · …\n\n…полный отчёт семейства в markdown…",
  "findings": [
    {
      "id": "CJM-01",
      "family": "cjm",
      "check": "L05",
      "severity": "critical",
      "steps": ["s3", "b1.s1"],
      "title": "Временную блокировку нельзя превратить в перевыпуск",
      "detail": "Что именно не так, с цитатой из входа",
      "evidence_class": "provided",
      "evidence_ref": "journey-map.md, строка 3",
      "consequence": "Что произойдёт с пользователем",
      "fix_hint": "Направление исправления, одна-две строки",
      "confidence": "high",
      "frequency": 2,
      "impact": 3,
      "useful_friction": false,
      "vision": ["V1"],
      "vision_status": "violated",
      "personas": ["p2", "p3"],
      "root_cause": "dead-end-failure"
    }
  ]
}
```

## Поля

| Поле | Обязательно | Значения |
|---|---|---|
| `id` | да | `CJM-NN`, `EDGE-NN`, `LOAD-NN`, уникально внутри файла |
| `family` | да | Совпадает с семейством файла |
| `check` | да | Код проверки семейства: `L05`, `E11`, `P-p3`, `C-s7`, `H3`, `V2` |
| `severity` | да | `critical` (К) — путь не выполняет задачу или вводит в заблуждение; `high` (В) — заметный провал опыта; `medium` (С) — пробел; `low` (Н) — качество карты |
| `steps` | да | Полные id шагов из journey.json или edge/branches.json; `[]` — про весь путь |
| `title` | да | До 90 знаков, факт, а не оценка |
| `evidence_class` | да | `provided` — предоставлено (во входе есть текст, экран, код, данные) · `absent` — нет во входе (вход молчит о том, что должно быть) · `synthetic` — синтетическое поведение · `interpretation` — интерпретация · `hypothesis` — гипотеза · `unknown` — неизвестно. Если находка опирается на факт и вывод из него, ставь класс факта, а вывод пиши в `detail` с пометкой «интерпретация:» |
| `evidence_ref` | при `provided` | Файл и место |
| `confidence` | да | `high` · `med` · `low` — уверенность в интерпретации |
| `frequency` | edge — да | 1–3: доля пользователей, которых касается |
| `impact` | edge — да | 1–3: неудобство · потеря времени или данных · вред, неверное решение, уход |
| `useful_friction` | нет | `true` — находка про трение, которое защищает пользователя: вердикт его ускоряет, но не убирает |
| `vision` / `vision_status` | нет | Пункты видения и статус: `covered` · `at-risk` · `violated` · `not-mentioned` |
| `personas` | нет | id персон, у которых проявилось (`check: "P"` при нескольких) |
| `root_cause` | нет, но очень желательно | Ярлык из списка ниже; по нему вердикт склеивает дубли между семействами |

## Ярлыки `root_cause`

Выбирай из списка, иначе вердикт не увидит, что три семейства нашли одну причину. Ярлык описывает причину, а не симптом: отказ без маршрута — `boundary-without-alternative` и для логики, и для краевых, и для нагрузки.

| Ярлык | Причина |
|---|---|
| `boundary-without-alternative` | Граница сервиса без маршрута, куда идти |
| `goal-contradiction` | Цель документа противоречит этапу |
| `value-failure` | Сервис не решает задачу; кнопкой не лечится |
| `silent-mode-switch` | Режим сменился, пользователю не сказали |
| `hidden-without-explanation` | Система скрыла или отклонила без объяснения |
| `unknown-wait` | Неизвестно, сколько ждать |
| `internal-language` | Внутренние слова продукта в интерфейсе |
| `no-return-path` | Нет возврата к прерванному или прошлому результату |
| `missing-role` | Не описана роль (представитель, сотрудник) |
| `merged-steps` | Несколько действий склеены в шаг |
| `mobile-context` | Путь не учитывает телефон и обстановку |
| `answer-overload` | Результат перегружен |
| `external-system-failure` | Сбой внешней системы не описан |
| `dead-end-failure` | Сбой без выхода |
| `map-vs-product-drift` | Карта расходится с работающим продуктом |
| `no-evidence` | Нет доказательств для ключевого шага |
| `no-emergency-path` | Нет пути для срочной ситуации |
| `data-error-without-fix` | Ошибку в данных нельзя исправить |
| `implementation-in-map` | Решения реализации внутри карты пути |
| `unrequested-scope` | Шаг, функция или обещание сверх задачи и видения |

Новый ярлык — только если ни один не подходит; объясни его в отчёте.

## Отчёт семейства: поле `report_md`

Некоторые среды запрещают субагентам создавать `.md`-файлы. Поэтому отчёт кладётся строкой markdown в поле `report_md` того же `findings.json`, а оркестратор разворачивает его в `<family>/report.md` командой `journey_check.py render <work>`. Не обходи такой запрет через shell.

Содержание `report_md`: что проверено, таблица находок, артефакты семейства (кривая, таблица нагрузки, сводка персон, развёрнутые ветки), «Передать другим семействам», «Не проверено», «Заметки о методе» (где инструкции семейства были неясны).

## Возврат оркестратору

Не больше 5 строк: находки по тяжести, главная находка, пути к файлам, что не проверено.

Свой файл проверяй так: `journey_check.py findings <work> --family <cjm|edge|load>` — чужие отсутствующие файлы тогда не мешают.
