# Слои сервиса (CJM + service blueprint)

Карта пути и сервисный блюпринт делят одни колонки-шаги. Сверху то, что переживает пользователь, снизу то, что делает сервис. Логические ошибки часто прячутся на стыке слоёв.

| Слой | Что в нём | Источник |
|---|---|---|
| Делает | Наблюдаемое действие пользователя | Факт: карта, код, запись сессии |
| Думает | Внутренний голос | Всегда догадка, помечай `assumption` |
| Чувствует | −2…+2 | См. `emotion-curve.md` |
| Боль / возможность | Трение и направление | Догадка, пока нет исследования |
| Видит (frontstage) | Экран, письмо, SMS, системный диалог — конкретно | Факт |
| За сценой (backstage) | Вызовы, задания, переходы состояний | Факт из кода или контракта |
| Опора (support) | Системы и сервисы под шагом | Факт |
| Доказательство | Интервью, аналитика, записи | Пусто, пока нет — заполняет человек |

## Проверки

| Код | Проверка |
|---|---|
| SL1 | Во frontstage нет слов из backstage: статусов, сущностей, кодов контрактов. Если есть, пользователь их увидит или карта врёт о том, что он видит (`root_cause: "internal-language"`) |
| SL2 | У каждого шага backstage, который занимает время или может упасть, есть frontstage-отражение: статус, ошибка, оценка времени |
| SL3 | Каждая система из support, от которой зависит шаг, имеет описанный сбой (см. L13) |
| SL4 | Колонки «думает», «боль», «возможность» помечены как догадки. Если они выданы за факт, это находка с классом «гипотеза» |
| SL5 | Действия системы, которые меняют то, что знает пользователь (сменился режим, данные не сверены, часть ответа скрыта), видны во frontstage. Скрытая смена режима — `К`, если из-за неё пользователь принимает решение на неверной основе |
| SL6 | Шаги, где backstage решает за пользователя (отклоняет, фильтрует, обрезает), объясняют во frontstage, что произошло и что делать |

Блюпринт целиком не рисуй. Таблица нужна только для шагов, где нашлась проблема стыка.
