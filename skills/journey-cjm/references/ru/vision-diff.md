# Сверка с видением владельца

## Статусы

| Статус (`vision_status`) | Когда |
|---|---|
| закрыт (`covered`) | Есть шаг, который выполняет пункт, и нет шага, который ему противоречит |
| под риском (`at-risk`) | Выполняется, но есть деталь, которая может его сломать (подсказка, текст, пример) |
| нарушен (`violated`) | Есть шаг, который прямо противоречит пункту |
| не упомянут (`not-mentioned`) | Ни один шаг пункт не затрагивает |

Статус пиши в находке полем `vision_status` (в journey.json не пиши — его не меняют). Скрипт `vision` ставит «закрыт» только по наличию ссылки на шаг, без проверки содержания: это черновик, каждый статус пересматривай.

## Что ИИ добавил без запроса

Отдельный список: шаги, функции, обещания, тон, которых нет в видении и которые не следуют из задачи пользователя. Для каждого: влияет ли на путь (добавляет шаг, решение, текст) и мешает ли пункту видения. Без оценки «хорошо» или «плохо»: решает владелец.

## Если видение восстановлено

Если у пункта `origin` не `owner`, в находках по нему ставь `confidence` не выше `med` — кроме противоречий внутри одного документа (цель против этапа): они верны независимо от подтверждения владельца, и пиши в отчёте: «видение восстановлено из <источник>, требуется подтверждение владельца».

## Находки

Нарушенный пункт — `К`, если он про безопасность, деньги, здоровье, право или главную задачу; иначе `В`. Не упомянутый пункт — `В`. Код проверки — id пункта (`V4`), `vision: ["V4"]`.
