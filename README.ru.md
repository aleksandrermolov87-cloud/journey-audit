# journey-audit — скиллы для аудита карты клиентского пути (CJM) агентами ИИ

**Находит, где путь клиента, собранный ИИ, расходится с реальностью: логические дыры, упущенные краевые сценарии, скрытую когнитивную нагрузку — и выдаёт приоритеты исправлений со спеками.**

> English version: [README.md](README.md)

ИИ пишет пути, которые выглядят законченными: каждый шаг удаётся, пользователь понимает всё с первого раза, внешние системы всегда отвечают. Человек, который знает продукт, видит три типа расхождений. `journey-audit` проверяет каждый своим агентом-аудитором, параллельно, а агент вердикта превращает находки в **приоритеты, измеримые цели и спеки, готовые к разработке**.

## Что получаете

| Аудитор | Ищет | Методы |
|---|---|---|
| **Логика CJM** | Этапы, противоречащие брифу; сбои без выхода; эмоции без причин; расхождение карты с работающим продуктом; сверка с видением владельца | 20 структурных проверок, кривая эмоций, слои сервисного блюпринта, ревью зрелой карты |
| **Краевые сценарии** | Прерывание и возврат, ошибки в данных, другие роли, сбои внешних систем, границы сервиса, недоставленная ценность, доступность | 14 осей краевых случаев, чек-листы флоу, синтетические персоны (в два этапа, без подсказки маршрута), альтернативные и смежные пути |
| **Когнитивная нагрузка** | Шаги, требующие больше решений, памяти и внимания, чем нужно для задачи; вероятные точки ухода | Индекс нагрузки с открытыми весами, модель KLM, усталость, 3 профиля персоны, эвристики Нильсена и Круга |
| **Вердикт** | Что чинить первым и что считать исправлением | Правила склейки и конфликтов, P0–P2, цели с метриками, спеки с Дано/Когда/Тогда, путь TO BE, план юзабилити-теста |

Результаты лежат в одной рабочей папке:

- `verdict/verdict.md` — Готов / Готов с условиями / Доработать / Переделать, цели P0–P2;
- `verdict/specs/G-NN.md` — спека на каждую цель P0/P1: проблема, метрика, фрагмент TO BE, состояния, тексты интерфейса, критерии приёмки, события аналитики, тест-кейсы;
- `verdict/backlog.json` — то же для трекеров и скриптов;
- отчёты семейств с кривой эмоций, таблицами нагрузки, ветками и результатами персон.

## Установка

**Плагином** (скиллы + четыре типа агентов, рекомендуется):

```text
/plugin marketplace add aleksandrermolov87-cloud/journey-audit
/plugin install journey-audit@journey-audit
```

**Только скиллы**, через открытый CLI для скиллов:

```bash
npx skills add aleksandrermolov87-cloud/journey-audit
```

**Вручную** — клонировать и скопировать пять папок скиллов в папку скиллов вашего агента:

```bash
git clone https://github.com/aleksandrermolov87-cloud/journey-audit.git
cp -r journey-audit/skills/* ~/.claude/skills/
```

Скиллы в открытом формате Agent Skills (`SKILL.md` с YAML-шапкой) — их подхватит любой агент, который читает скиллы из папки. Агентам без поддержки скиллов — [AGENTS.md](AGENTS.md). Нужен только Python 3.8+ для вспомогательного скрипта.

## Как пользоваться

Простыми словами, по-русски или по-английски:

```text
Проверь CJM в docs/onboarding-cjm.md: логика, краевые сценарии, нагрузка. Дай приоритеты и спеки.
Моё видение: пользователь проходит настройку за один подход; мы не спрашиваем то, что уже знаем.
```

```text
Какие краевые сценарии мы упустили в оформлении заказа? Прогони 4 персоны по прототипу https://staging.example.com
```

Режимы: полный аудит (по умолчанию), быстрый (без персон и развёрнутых веток), одно семейство или только вердикт по готовым находкам.

| Скилл | Роль | Вызывать напрямую, когда нужно |
|---|---|---|
| [`journey-audit`](skills/journey-audit/SKILL.ru.md) | Оркестратор: рамка, нормализация, запуск, сборка | Полный аудит |
| [`journey-cjm`](skills/journey-cjm/SKILL.ru.md) | Семейство логики CJM | Только логика карты |
| [`journey-edge`](skills/journey-edge/SKILL.ru.md) | Семейство краевых сценариев | Только упущенные сценарии, персоны |
| [`journey-load`](skills/journey-load/SKILL.ru.md) | Семейство когнитивной нагрузки | Только нагрузка, AS IS против TO BE |
| [`journey-verdict`](skills/journey-verdict/SKILL.ru.md) | Вердикт, приоритеты, спеки | Приоритеты и спеки по готовым находкам |

Агенты (при установке плагином): `journey-cjm-auditor`, `journey-edge-auditor`, `journey-load-auditor`, `journey-verdict`. Их брифы — в [`skills/journey-audit/agents/`](skills/journey-audit/agents).

Каждый скилл есть на английском (`SKILL.md`, `references/`) и на русском (`SKILL.ru.md`, `references/ru/`). Агент отвечает на языке пользователя.

## Пример

[`examples/card-reissue`](examples/card-reissue) — путь «перевыпуск потерянной карты» в мобильном банке, набросанный ИИ и проверенный целиком: исходная карта, нормализованный JSON, три отчёта семейств, вердикт, спеки.

Итог: **Rework (доработать)** — 37 находок сведены в 3 цели P0 и 5 целей P1. Главное: задача звучит как «продолжать платить сегодня», а ни один шаг пути от ИИ не даёт заплатить 5–7 дней до прихода новой карты. Пример написан на английском: [итог на одну страницу](examples/card-reissue/audit/journey-audit-card-reissue.md), [вердикт](examples/card-reissue/audit/verdict/verdict.md).

```bash
python3 skills/journey-audit/scripts/journey_check.py check examples/card-reissue/journey.json --lang ru
python3 skills/journey-audit/scripts/journey_check.py load  examples/card-reissue/journey.json --lang ru --persona-tech low --persona-patience low
```

## Как аудит остаётся честным

- **Классы доказательности не смешиваются.** Каждая находка — `provided`, `absent`, `interpretation`, `synthetic`, `hypothesis` или `unknown`. Синтетические персоны и модель нагрузки дают гипотезы, а не факты.
- **Экраны не выдумываются.** Чего нет во входе, то остаётся `unknown`.
- **Аудиторы независимы.** До вердикта они не читают находок друг друга.
- **Полезное трение остаётся.** Подтверждение необратимого, согласие, юридические шаги и шаги безопасности ускоряются, но не убираются.
- **Провал ценности называется прямо.** Если сервис не решает задачу, вердикт ставит бизнес-цель, а не правку интерфейса.
- **Решения владельца — за владельцем.** Границы сервиса, юридические, медицинские и финансовые рамки — списком вариантов.

## Вопросы

**Заменяет ли это исследование пользователей?** Нет. Аудит говорит, что проверять и на ком; каждая P0, которая держится на гипотезе, идёт с заданием для проверки.

**Можно ли проверить путь, написанный человеком?** Да. Проверки те же; пути от ИИ просто чаще их не проходят.

**Какие входы подходят?** Таблица CJM, документ, user flow, скриншоты, URL прототипа, код фронта — или их сочетание.

**Отправляет ли режим браузера формы?** Нет. Он читает страницы и останавливается перед отправкой, оплатой и регистрацией.

**Можно ли настроить модель нагрузки?** Да. Веса описаны в [`cognitive-load.md`](skills/journey-load/references/ru/cognitive-load.md) и живут в одной функции скрипта.
